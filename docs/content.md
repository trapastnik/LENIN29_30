> ⚠️ **Руками json больше не редактируются.** С вехи M1b контент приезжает из
> docx заказчика скриптом, и ручная правка сгенерированного файла затирается
> следующим прогоном. Правка идёт в `<id>.patch.json` либо в сам импортёр —
> см. [content-schema.md §11](content-schema.md#11-трёхфайловая-модель).

Схема и все её «почему» — [content-schema.md](content-schema.md).

## Индекс = то, что UI может показать

`_index.json` содержит **только записи с файлом справки**. Раньше импорт досевал
туда все закреплённые id заглушками `stub: true` — на случай, если словарь
алиасов сошлётся на ещё не импортированную справку. Ссылок на такие записи
не оказалось ни одной, а UI считает раздел по длине `items` и рисует плитку
на каждый элемент: получались завышенные счётчики (69 / 78 / 34 вместо
59 / 70 / 33) и карточки-призраки, открывающиеся в пустоту.

Нет файла — нет записи. Id при этом остаётся закреплённым в `_ids.json`
(реестр append-only), так что при поставке справки запись вернётся с тем же id.
Ловится валидатором: запись индекса без файла — **ошибка**, а не заглушка.

### Подпись плитки хранится, только если помечена (`title_locked`)

Подпись намеренно отличается от заголовка справки: на плитке «РСФСР»,
в справке «Российская Социалистическая Федеративная Советская Республика».
Таких записей **110 из 198**, и каждая — решение человека.

Раньше импорт хранил их правилом «записывать, только если пусто», а оно
консервирует всё подряд — и выбранное, и затёкшее однажды. Так у семи
персон на плитке жило дореформенное написание из подборки M0 («Деникинъ»
против «А. И. ДЕНИКИН» в справке), пережившее все пересчёты. Отличить одно
от другого было нечем: тот же механизм, что держал `camp` Авксентьева
зелёным при красной справке.

Теперь подпись хранится, **только если стоит `title_locked`** — по образцу
`xy_locked` у координат Венна. Непомеченная пересчитывается из справки:
новая сущность получит на плитку полное название, это длинно и сразу видно,
а значит чинится. Молчаливая заморозка не видна вовсе.

Пометку ставит `scripts/import/seed_index_titles.py`, он же держит правку
семи написаний (решение dvn 2026-08-05: «как все остальные»). Регистр
подписи при этом **не трогается** — 55 ПРОПИСНЫМИ, 12 обычным регистром,
3 с инициалами — это отдельный вопрос, он не решён.

**Проверка — снять пометку и прогнать импорт:** «РСФСР» обязан смениться
на полное название. Замок, который ни разу не видели работающим, ничем
не отличается от комментария.

Плитке годится **любая** картинка справки с собранными производными, а не
обязательно первая по порядку: у Милюкова заказчик не прислал `_01`, но в
карточке ещё четыре фотографии, и при жёсткой привязке к `slot: "lead"` плитка
оставалась пустой при непустой карточке. Порядок внутри карточки при этом
не меняется — отсутствующая аннотация остаётся аннотацией №1.

Нет ни одной картинки с производными — ключей `lead_*` в записи **нет вовсе**.
`lead_media: null` хуже отсутствующего поля: UI не обязан отличать одно от
другого и уходит рисовать миниатюру по пустому пути. Ошибка валидатора.

Рядом с `lead_media` обязан лежать **`lead_tiers`** — список собранных тиров.
Достроить имя файла по шаблону нельзя: апскейла нет, у мелких сканов тиров
меньше трёх, и `mediaUrl()` в зоне `ui` без списка честно возвращает `null`.
Миниатюра остаётся заглушкой при собранных и отдающихся по http производных —
дефект, который глазами виден только на витрине. Тоже ошибка валидатора.

## Связи справки (`public/content/_backlinks.json`)

Все связи справки в обе стороны — с кем она связана и кто связан с ней.
На киоске посмотреть больше негде: внешнего поиска нет.

**Почему сюда вошли и прямые связи, хотя они уже размечены в тексте.**
Довод «в тексте они есть» верен только там, где по ним можно перейти,
а строчная ссылка **некликабельна** намеренно (`rich-text.js:50`: тач-цель
высотой строки — «перехваченная цель» из §1 CLAUDE.md). Значит подсвеченный
термин виден и никуда не ведёт, и обратные связи его не заменяют:
«Большевики упоминают Ленина» и «Ленин упоминает Большевиков» — разные
факты, второй не следует из первого. Вскрыл dvn 2026-08-05; моя первая
форма несла только обратные, и это была дыра.

Генерируется `scripts/import/backlinks.py`, **руками не правится**, идёт
последним шагом импорта (читает слитые справки с диска, поэтому обязан быть
после записи всех разделов). Форма согласована с оркестратором 2026-08-05.

```jsonc
"kolchak": {
  "out":    [ { "id": "…", "kind": "state", "title_ru": "…", "n": 3 } ],
  "refs":   [ { "id": "…", "kind": "state", "title_ru": "…", "n": 11 } ],
  "mutual": [ { "id": "…", "kind": "party", "title_ru": "…",
                "n_out": 3, "n_in": 2 } ],
  "more": 46,                      // хвост ТОЛЬКО у refs; 0 — ключа нет
  "chronicle_mentions": 17         // строк хроники упоминают; 0 — ключа нет
}
```

**Три группы, и они не пересекаются.** `out` — на кого ссылается эта
справка, `refs` — кто ссылается на неё, `mutual` — взаимные, с силой
в обе стороны. Разрез чистый намеренно: положи взаимные в обе группы —
и **119 карточек из 198** покажут одну кнопку дважды подряд (максимум 7
повторов на карточке). Отношение и правда разное, но кнопка выглядит
одинаково, и это читается как поломка.

⚠️ **Потолок действует ТОЛЬКО на `refs`.** У исходящих потолка нет,
и это не забывчивость: у них есть **видимый эталон** — подсвеченные
термины в самом тексте справки. Урежь до восьми, и десять подсветок
останутся без кнопки; посетитель увидит несоответствие. У входящих
эталона нет вовсе, там потолок незаметен. Замер: потолок на `out`
экономит 6 КБ из 129 — то есть решает вид, а не вес.

Прямые связи вошли в файл потому, что **строчная ссылка некликабельна**
(`rich-text.js:50` — тач-цель высотой строки). Довод «они уже в тексте»
верен только там, где по ним можно перейти.

`kind` — сегмент из синтаксиса ссылок (`#/person/lenin`), **не** каталог:
`person`, `party`, `state`, `event`. `title_ru` лежит рядом намеренно: разделы
живут на четырёх разных страницах, и без него потребителю пришлось бы грузить
все четыре `_index.json` ради подписей на кнопках. Цена — **366 КБ**: подписи
и есть вес файла, поэтому потолки его почти не меняют. Против ~5 МБ
контента это одна незаметная загрузка.

`n` — сколько раз источник упомянул цель; `related` даёт 1, если
в тексте упоминания не было. Порядок: сила ↓, затем вид, затем заголовок —
не по алфавиту. Сигнал настоящий: у 478 связей из 1451 сила больше единицы.

**Два счётчика хроники, а не один.** `chronicle_mentions` — строка упоминает
сущность в тексте; `chronicle_jumps` — строка ведёт кнопкой на карточку
события. Механизма два, и они непересекающиеся: событие не бывает целью
ссылки (в тексте справок нет ни одного `#/event/`, и `related` на события
не ссылается ни разу — проверено по всем 198). Одно поле с разным смыслом
по виду записи — двусмысленность, из которой через месяц выходит неверная
подпись на экране.

**Ключа нет, если показывать нечего** — не пустой массив. Пустое «связанные
справки: —» читается как поломка движка. Правило потребителю одно: нет
ключа — нет группы. После добавления исходящих запись есть у всех 198:
без единой связи не осталось никого.

⚠️ **У 36 событий нет входящих связей вовсе** — на них не ссылается ни один
текст, они достижимы только кнопкой из хроники. Их блок держится
на `out` и `chronicle_jumps`. Это факт данных, а не недоделка: заказчик
в тексте события не упоминает.

Свежесть ловится `npm run content:check` — валидатор зовёт
`backlinks.py --check`, который пересчитывает **по справкам** и сравнивает
с закоммиченным файлом. Не сверка выхода генератора с выходом того же
генератора: та доказывает детерминированность, а не правильность.
Пустой вход — сбой, а не «связей нет». Проверено четырьмя пробами:
несвежий файл, отсутствующий файл, недоступный python3, пустой вход —
каждая даёт своё сообщение.

**Отдельно проверяется чистота разреза** — что три группы разрезали один
граф без пропаж и пересечений: если `A` числит `B` в `out`, то `B` обязан
числить `A` в `refs` (либо оба во `mutual`), а списки не должны пересекаться.
Сверяется 1451 пара каждым прогоном. Без этого каждая группа по отдельности
выглядит осмысленной при любой ошибке разреза — потерю видно только
сверкой пары. Проверено пробой: перенесла связь из `mutual` в `out`,
гейт назвал именно её.

## Лагерь партии (`scripts/import/seed_party_camps.py`)

Тринадцать партий, импортированных сверх кураторских двадцати, размечены
**явной таблицей**, а не эвристикой. Разбор регалий, закрывший 68 личностей
из 70, на партиях не работает: строки регалий у партии нет, решает этнический
определитель в названии. Классификатор оставил без ответа Бунд, Поалей Цион
и УСДРП и утащил в революционную демократию Белорусскую громаду и Грузинскую
СДП — партии, которые в разделе стоят среди национальных.

Лагерь проставляется через `<id>.patch.json`, а не машинным слепком: он тянет
за собой `venn_groups`. Координаты `x`/`y` при этом НЕ выдаются — раскладку
диаграммы ведёт зона `ui`; партия без координат не встаёт на диаграмму, зато
попадает в фильтр.

Три случая спорны, и это помечено прямо в таблице скрипта — лагерь взят
по разделу витрины, а не по идеологии; переключается правкой одной строки:

| партия | взято | альтернатива |
|---|---|---|
| Грузинская СДП | `national` — правящая партия ГДР | `rev-dem` по идеологии (и `person/zhordaniya` размечен так) |
| СДП Финляндии | `national` | `red` — в 1918 возглавила Финляндскую Социалистическую Рабочую Республику |
| Боротьбисты | `national` | `red` — в 1920 влилась в КП(б)У |

⚠️ Та же развилка есть у личностей: Милюков и Набоков размечены `rev-dem`
(через Временное правительство), хотя партия `cadets` в индексе отнесена
к белым. Подключать таксономию партий сигналом к личностям нельзя — она
утащит Букейханова в белые из-за первой строки «Член ЦК Конституционно-
демократической партии», хотя он глава правительства Алашской автономии.

## Лонгриды (`public/content/longreads/`, зона `simbirsk`)

Схема `longread.schema.json` — единственная схема контента не за авторством
зоны `content`; ратифицирована при мерже M1e. Общий конверт взят один в один:
`schema: 1`, пары `*_ru`/`*_en`, `en_status`, `related`, `src`, `flags`,
ключ слияния `n`.

Устройство другое, поэтому валидатор обходит их **отдельным проходом**: текста
на верхнем уровне нет (`summary_ru` пуст), всё разложено по секциям, медиа
и ссылки живут внутри них. Лонгрид без `_index.json` — он один на раздел, —
но его id заводится в общую таблицу разрешения, чтобы на него можно было
сослаться из справки через `related.longreads`.

**`ref_labels` — денормализованный кэш подписей** из наших индексов
(`id → {kind, title_ru, camp, href}`). Он нужен не из лени: киоск запускается
по `file://`, где `fetch` **и** `XMLHttpRequest` запрещены — проверено в Chrome,
без `--allow-file-access-from-files` оба падают с «Failed to fetch». Подтянуть
индекс, чтобы подписать плашку связи, нечем.

Плата за кэш — он протухает от переименования в индексе, и молча. Поэтому
`content:check` сверяет каждую запись `ref_labels` с индексом: `kind`,
`title_ru`, `camp`. Расхождение — **ошибка**, а не предупреждение. Первый же
прогон поймал три протухших `camp` (`dutov`, `kappel`, `sverdlov`): лонгрид
был собран до того, как лагеря проставились.

## Чем проверяется проверка

Полный свод — [checks.md](checks.md): семь правил и четыре уточнения, с
примерами и способом проверки каждого. Ниже — только то, что касается этой
зоны напрямую.

Четыре уточнения, накопившиеся в обмене с зонами `maps` и `simbirsk`.
Они не про контент, а про то, как устроены проверки в этой зоне, — и каждое
куплено ошибкой, своей или соседней.

**Красное должно дать то самое правило.** Увидеть проверку сработавшей мало:
подставив дефект в `media[].files`, я получила красный гейт и решила, что
правило про части живо. Красное дала соседняя проверка — подставленный путь
заодно не существовал, и сработало «заявлен тир, файла нет». Правило про
части могло быть мёртвым, и я бы этого не узнала. Переподставила так, чтобы
путь был настоящим: `частей 2, а путей производных 1` — живое. Проверять надо
не факт падения, а текст сообщения.

**Вырезание и проверка — разные роли** (формулировка зоны `simbirsk`).
Вырезание отвечает за «не испортить хорошее», проверка — за «не пропустить
плохое». У позиционного правила («срезать хвост в скобках») ошибка первого
рода: съест «(1919 г.)» из названия. У шаблонного («срезать по списку
формулировок») — второго: новая формулировка заказчика проедет молча.
Выбор между ними ложный, нужны оба, и в разных местах.

**«Мусор» и «нужное не на своём месте» чинятся по-разному** (тоже
`simbirsk`). Правило «редакторская пометка в подписи — ошибка» описывает
обнаружение. Дальше развилка: если пометка дублируется в отведённом месте —
удалить (наш случай, все 282 `note_ru` были в `_notes.json`); если копия
единственная и по делу — **переставить**, а удалить нельзя. Спутав, второй
случай теряешь навсегда и молча.

**Совет по памяти о собственном коде — тот же пересказ вместо чтения.**
Я посоветовала соседней зоне позиционную регулярку, а потом обнаружила, что
у себя вырезаю по содержимому (регулярка инвентарного номера), а не по месту.
Позиционного вырезания у меня нет вовсе. Тот же класс, что чтение
устаревшей копии CLAUDE.md, только про свой файл.

## Связь со слоем карт: что решено и что отложено

`territory_id` ставится импортом по реестру `public/content/geo/_index.json`
(зона `maps`) — только там, где `polygon` непустой. Шесть записей из 59.

### Собранная карта доехала до карточки (`map_id` + `initial_layers`)

`territory_id` ведёт в реестр геометрии, но карточку рисует не он:
`state-card.js:229` читает `map_id`, `:231` — массив `initial_layers`.
Пока их не было, три карты, собранные зоной `maps` (`territories`,
`allies-entente-presence`, `czechoslovak-corps-corridor`), лежали готовыми
и не показывались — седьмой случай класса «обе стороны зелёные».

`scripts/import/seed_territory_maps.py` связал шесть справок с territory_id:
**соответствие выводится из паспортов карт, а не пишется таблицей**, и
каждое проверяется по факту. Две стратегии — слой ровно с именем
`territory_id` (тогда карта `territories`, слои `[background, <id>]`) либо
карта, чей id начинается с `territory_id` (своя проекция, умолчания
паспорта). Не нашлось — запись пропускается с печатью: догадка тут хуже
пропуска, неверный слой покажет чужую территорию под верной подписью.

⚠️ **`initial-layers` ЗАМЕЩАЕТ умолчания паспорта, а не дополняет.**
У карты `territories` в умолчаниях включены разом РСФСР, Колчак, Временное
правительство и СССР — карточка РСФСР без явного списка показала бы все
четыре территории. Поэтому список обязателен и включает `background`:
не впишешь — пропадёт подложка.

Ворота в обе стороны (`validate-content.mjs`): `map_id` в несуществующую
карту и слой не из паспорта — **ошибка** (молчаливая подмена: карта
покажет то, что осталось включённым); собранная карта без ссылок —
предупреждение. Обратная половина считает ссылки и в разметке страниц,
иначе объявила бы ненужной ту карту, что показывает `demo-povolzhye.html`.

Проверено на живом `dist` (вьюпорт 1920 при DPR 2): карточка РСФСР —
`map-id=territories`, `initial-layers=background,rsfsr`, видимых слоёв
2 из 12, бокс 1156×520. ⚠️ Слои прячутся через **`visibility`**, а не
`display` — мерить надо его.

**Отложено намеренно, до ответа музея, одним пакетом:**

`polygon: null` слепляет три разных состояния — «полигон собран» (6),
«картография заказчика есть, контур в работе» (9 регионных листов) и
«картографии нет» (44, из них у трёх территории может не быть по смыслу:
Политцентр, Кронштадт, Уфимская директория).

Первые два состояния выводимы из уже существующих полей, третье — суждение,
и его зона `maps` заведёт признаком `territory: "none"`; отсутствие поля
означает «территория будет». **Признак я протащу в карточку и индекс тем же
механизмом, что `territory_id`** — иначе он останется в чужом файле, куда
потребитель карточки не смотрит, и получится буквальный повтор истории
с Комучем: `map_id` жил только в индексе, «карта есть» считалось по справке,
карта не показалась ни разу.

Смягчать правило до «есть `phases`» сейчас **не нужно**: это имеет смысл
только если для «контур в работе» и «картографии нет» захотят разные
заглушки, а это то же решение про текст заглушки, что и `territory: "none"`.
Двумя заходами вместо одного его примут разные люди в разное время.

Плюс девять регионных листов могут исчезнуть из вопроса сами: они ждут
подробного источника базы, и с его приездом станут собранными.

## Чужие файлы в `content-src/`

По §4 каталог целиком за зоной `content`, но два файла в нём пишет
`simbirsk`, и это согласовано:

| файл | владелец | зачем |
|---|---|---|
| `simbirsk-media-wanted.md` | `simbirsk` | выдан заданием M1e точечно |
| `simbirsk-placeholders.json` | `simbirsk` | запись обхода Госкаталога |

Сегодня им ничто не грозит: импорт пишет только поимённо и обходит
рекурсивно один `../IN/**/*.docx`. **Опасность появится в тот день, когда
кто-нибудь добавит сюда чистку каталога** — например «убрать отчёты старше
недели». Тогда эти два файла исчезнут молча и не у нас.

Поэтому: любая операция, которая ходит по `content-src/` списком, а не
по имени, обязана исключить `simbirsk-*`.

## Обязательный вход читается жёстко

Правило «чужой файл читается через *есть — берём, нет — работаем без него*»
верно **не всегда**, и поправку принесла зона `simbirsk`.

Мягкое чтение годится для **необязательного** входа: нет подборки персон
из design-pass — импорт обходится, лагерь берётся из регалий. А вот если
без файла результат получается пустым, но правдоподобным, мягкое чтение
превращается в тот самый «зелёный и неверный» прогон: у неё без наших
индексов `ref_labels` собрался бы пустым, плашки связей исчезли бы со всех
одиннадцати разделов, и сборка отчиталась бы успехом.

Правило точнее звучит так: **необязательный вход — мягко, обязательный —
жёстко, но с внятным отказом.** Не трассировкой: сообщение обязано назвать
файл и владельца, чтобы читающий понял, к кому идти.

## Временные иллюстрации (`placeholder`)

Заказчик поставил не все изображения. Там, где их нет, в проект ставится
превью с Госкаталога — временно, пока идёт запрос официальных файлов.
Такая картинка помечается в `media[]`:

| поле | что |
|---|---|
| `placeholder: true` | это не поставка, а превью |
| `source_url` | позиция в Госкаталоге |
| `holder_ru` | держатель, напр. ОГАУК «Ленинский мемориал» |
| `gk_no` | номер в Госкаталоге |
| `kp_no` | номер по книге поступлений |

Поле живёт в `common#/definitions/media`, а не в схеме лонгрида: недодать
могут в любом разделе.

`content:check` печатает их число **отдельной громкой строкой с разбивкой
по держателям**, но гейтом это не делает: заглушки обязаны спокойно жить,
пока идёт запрос, а вечно красная проверка учит себя игнорировать. Заменить
их надо до приёмки, а не до мержа. Единственное, на что валидатор ругается, —
`placeholder` без `source_url`: заменить такую картинку будет нечем.

Медиа лонгрида могут не иметь файла вовсе — изображение живёт в госкаталоге.
Для этого в `common#/definitions/media` добавлены `source_url`
и `source_note_ru`; при заполненном `source_url` отсутствие файла
не считается пропажей и не даёт предупреждения.

## Медиа-конвейер (`scripts/media/`)

```bash
python3 scripts/media/build_media.py            # инкрементально
python3 scripts/media/build_media.py --only lenin
python3 scripts/media/build_media.py --force
```

Оригиналы (1.6 ГБ, 118 из них TIF) остаются в `../IN/`. Собирается WebP
в трёх тирах — **рамки, а не размеры**: картинка вписывается, пропорции целы.

| тир | рамка | где нужен |
|---|---|---|
| `lg` | 2400×1500 | карточка справки, лайтбокс на 4K |
| `sm` | 1280×900 | плитка, лента хроники |
| `xs` | 560×560 | превью, миниатюра |

**Апскейла нет.** У 39 % фонда длинная сторона меньше 1600 px; растянуть такой
скан до 2400 — показать на киоске мыло вместо экспоната. Если оригинал влезает
в рамку целиком, тир равен нативу, а совпавший с уже собранным тиром покрупнее
не пишется вовсе. Поэтому у 97 изображений тиров меньше трёх — **читать надо
`media[].tiers`, а не гадать по имени файла.**

Двусторонние (купюры, развороты) дают несколько производных на одну запись:
`05`, `05p2`. Полный список — в `media[].files`, `file` остаётся первым из них.

Что куда:

| | |
|---|---|
| `public/content/media/**` | производные, **в `.gitignore`** |
| `content-src/_media-manifest.json` | что собрано — **коммитится** |
| `content-src/_media-build.json` | штамп сборки — **не коммитится** |

**Штамп лежит отдельно от манифеста, и это главное в его устройстве.**
Манифест обязан совпадать побайтово между машинами: по этому совпадению
проверяется целостность оригиналов на сервере (CLAUDE.md §7). Коммит и дата
внутри него сделали бы файл разным при каждой пересборке с другого коммита —
и убили бы ровно ту проверку, ради которой манифест живёт. Проверено:
после прогона со штампом манифест побайтово тот же.

Зачем штамп вообще нужен: **у манифеста нет и не может быть `--check`.**
Пересобрать его можно только там, где лежит `../IN/`, — на сервере и на маке,
больше нигде. Там, где `--check` есть (`tokens.css`, `build/*.js`,
`_backlinks.json`), штамп строго слабее: он отвечает «когда сделан»,
а `--check` — «верен ли сейчас».

Штамп несёт коммит, ветку, **состояние дерева**, машину и дату. Грязное
дерево важнее самого коммита: производные собраны не с того, что лежит
в коммите, а по хешу это неотличимо.

Манифест коммитится, а производные нет, и это не оплошность: `tiers` в справках
обязаны быть одинаковыми на любой машине, включая ту, где `../IN/` нет и
пересобрать нечем. Манифест читает `run_import.py` и проставляет `tiers`
и `files`. Смотреть вместо этого на диск нельзя — поле начнёт то появляться,
то исчезать, и каждый прогон импорта даст разный diff.

Порядок: **`media:build` → `run_import` → `content:check`.** Валидатор требует
наличия файлов тиров только там, где каталог `media/` вообще есть, иначе ворота
краснели бы на сервере и в свежем клоне на пустом месте.

⚠️ **Производные не доезжают до stage.** Сервер собирает из git, `media/`
в `.gitignore` — значит в `dist/` на сервере картинок нет, и раздел показывает
серые заглушки. Собранный фонд — **237 МБ** (`lg` 150 · `sm` 65 · `xs` 22),
а потолок `public/content/` по CLAUDE.md §6 — 250 МБ, и весь каталог уже 256 МБ.
Развязка — решение оркестратора, `.gitignore` и `deploy/` не наша зона. Варианты:
снизить качество WebP (q=82 → 75 даёт ~190 МБ, → 70 даёт ~176 МБ) и коммитить;
либо возить `media/` на сервер отдельно от git, добавив `--exclude=content/media`
в `rsync --delete` деплоя.

## Заявки другим зонам по итогам M1b

Своими файлами это не чинится — нужны владельцы.

### Оркестратору (`package.json`)

Скрипты валидатора и импорта в `package.json` не прописаны: файл ведёт
оркестратор. Пока `content:check` запускается напрямую (`node
scripts/validate-content.mjs`). Просьба добавить:

```json
"content:check": "node scripts/validate-content.mjs",
"content:import": "python3 scripts/import/run_import.py"
```

и включить `content:check` в общий `npm run check` — §7 CLAUDE.md его уже
требует, а команды нет.

### Зоне `ui` — три следствия схемы, видимые на экране

1. **`summary_ru` теперь markdown.** Ссылки на другие справки лежат прямо
   в тексте: `[большевиков](#/party/bolsheviks)`, неразрезолвленное —
   `***жирным курсивом***`. Сейчас `party-card.js:135` и `state-card.js:145`
   режут текст по `\n\n` и заворачивают в `<p>`, поэтому **разметка видна
   на экране как есть**. Нужен минимальный рендерер (ссылка, `***`, `**`, `*`)
   и обработчик перехода по `#/kind/id`.
2. **`abbr_ru` стал массивом** — аббревиатур бывает несколько
   (`["РСДРП(б)", "РКП(б)"]`). `state-card.js:154` печатает поле напрямую,
   получится «РСДРП(б),РКП(б)». Нужен `join(' · ')`.
3. **Индекс стал самодостаточным**: `lead_media` + `lead_w`/`lead_h`,
   `dates_display_ru`, `has_card`, `stub`, `sort_key_ru`, `title_full_ru`.
   Плитка рисуется без единой дозагрузки. Карточки сейчас собирают даты как
   `dates.from — dates.to`; правильнее показывать `dates.display_ru` — строку
   заказчика: «Конец октября – начало ноября» цифрами не передать.

Плюс вопрос: **`venn_groups` заполняется вручную по 33 записям** (~час).
Импорт кладёт туда один текущий `camp` как заглушку и её не перетирает.
Без ручного прохода диаграмма Венна остаётся картинкой.

### Зоне `ui` — блок связей ждёт глубоких ссылок (решение оркестратора)

Данные готовы (`_backlinks.json`, 198 записей), но **пути показа у них нет**.
Замер: 65 % кнопок ведут на карточку с ДРУГОЙ страницы. Разделы разведены
по четырём страницам — `parties.html`, `states.html`,

`#/party/bolsheviks` никуда не ведёт по устройству.

🔒 **Решение оркестратора 2026-08-05: делаем глубокие ссылки, а не урезаем
блок.** Мой первый вариант — рисовать только 35 % внутристраничных связей,
остальные числом — **отклонён**: урезанный блок даёт то же, от чего уходим,
связь видна и не работает. Нужен механизм «страница читает `location.hash`
при загрузке и открывает карточку той же модалкой» — четыре страницы, один
приём, он же закроет 77 переходов хроники на карточки событий
(`chronicle_jumps`). Задача `ui` **отдельно от блока**: сначала механизм,
потом вёрстка. От `content` больше ничего не нужно — три поля отданы.

### Зоне `maps`

`territory_id` стоит у **6 справок из 59** — там, где у записи реестра
`public/content/geo/_index.json` непустой `polygon`. У остальных `null`,

с карточкой (`map_id`/`initial_layers`) — см. «Собранная карта доехала
до карточки» выше.

## Как добавить справку

Никак вручную. Кладём docx в `../IN/`, гоняем импорт:

```bash
python3 scripts/import/run_import.py --kind party --only "Название"
```

Если нужно поправить результат — рядом с `<id>.json` кладётся
`<id>.patch.json` с одними только правками; `null` в патче удаляет поле.
