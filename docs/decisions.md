### Две дорожки доставки: код и медиа

Раньше канал был один — git, — и из этого следовало, что «не в git» значит
«не на киоске». Теперь их две, и путать их нельзя.

| | код и контентный json | производные медиа |
|---|---|---|
| Объём | ~5 МБ текста | ~200 МБ бинарей |
| Канал | git → `git pull` на сервере | `npm run media:build` **на сервере** |
| Где живёт | репозиторий | `/var/www/mtk29/content/media/` |
| Диффы | осмысленные, ревьюятся | никакие |

⚠️ **Единственное исключение — временные изображения Госкаталога**
(`public/longread/placeholders/`, 476 КБ на 24 файла). Их нельзя
пересобрать на сервере: для этого пришлось бы ходить наружу при каждой
сборке, а киоск офлайн и в Госкаталог не ходит никто. Ратифицировано
2026-08-03. Когда музей отдаст оригиналы — каталог исчезает целиком.
Счётчик «временных N, выкупленных M» печатает импорт зоны `simbirsk`.

Производные **никогда не едут в git** — они регенерируются побайтово, а git
хранит каждую версию навсегда. Но и заливать их с мака не надо: с 2026-08-02
оригиналы лежат на сервере в `/root/mtk29-in/` (симлинк `/root/IN`, потому что
`build_media.py` ищет их по `../IN/` от корня репозитория), и конвейер гоняется
там же.

⚠️ Поэтому в деплое стоит `--exclude=content/media/`. **Без него `rsync --delete`
сносит все производные при каждом деплое кода** — и раздел уходит в заглушки
без единой ошибки.

Обратная сторона того же исключения: деплой кода производные и **не приносит**.
Медиа заливаются своей командой, и только когда менялись:

```bash
ssh ostrov 'cd /root/mtk29-src && npm run media:build \
  && rsync -a public/content/media/ /var/www/mtk29/content/media/'
```

Полный прогон переписывает `content-src/_media-manifest.json`. Он должен
совпасть с закоммиченным — это заодно проверка целостности оригиналов на
сервере. Разошёлся — разбираться, а не коммитить поверх.

`content-src/_media-manifest.json` **коммитится** — он фиксирует, какие тиры
собраны. Поле `tiers` в справках обязано совпадать на любой машине, включая
те, где оригиналов нет и пересобрать нечем.

**Оригиналы теперь в двух местах** — `../IN/` на маке и `/root/mtk29-in/` на
ostrov. Это не бэкап (одна машина, снимков нет), но лучше единственной копии.
Наружу не отдаются: каталог вне `/var/www/`.

**Деплой — только через GitHub, прямой rsync с Mac запрещён:**
```bash
git push origin main
ssh ostrov 'cd /root/mtk29-src && git pull --ff-only && npm run build \
  && rsync -a --delete --exclude=nginx.conf --exclude=content/media/ dist/ /var/www/mtk29/ \
  && cp deploy/nginx.conf /var/www/mtk29/nginx.conf \
  && docker exec mtk29-web nginx -s reload'
```
⚠️ На ostrov fail2ban банит при серии частых ssh-попыток (10+ минут).
Делать **одну** ssh-команду с полным деплоем в один заход.

**Теги:** `pre-<имя-мержа>` перед каждым крупным слиянием, `prod-YYYY-MM-DD`
перед каждым деплоем. Откат = сброс серверного чекаута на тег + пересборка.

дал шапке `background-color: rgba(0,0,0,0)` и чёрный текст на сером —
не «унаследованный цвет», а отброшенное объявление. То же у
`calc(1180px * var(--ui-scale))` без запаса: колонка чтения расплылась
на всю ширину. Отсюда и правило ниже — запас у метрики не формальность,
а единственное, что отделяет «значение по умолчанию» от «правила нет».

- ✅ **`var(--x, 120px)` для РАЗМЕРОВ и МЕТРИК — наоборот, обязателен.**
  Разведено 2026-08-03 после разбора зоны `ui`. Для цвета запас маскирует
  ошибку, для метрики он единственное, что спасает приёмочный параметр при
  отсутствующем токене: сцена `/expo/` месяц шла без `tokens.css`, и
  `var(--touch-hit, 120px)` сохранил тач-цель, а `var(--touch-hit)` без
  запаса в `brand.html:632` дал бы `min-height: auto` молча.
  **Снятие запаса у метрики «по правилу» — само нарушение.**
- ❌ **Курсив на Nolde** (`--font-display`). Файла курсивного начертания нет,
  браузер синтезирует наклон — на крупных кеглях это видно как дефект засечек.
  Курсив 20 Kopeek и 21 Cent легален, файлы подключены.
- ❌ **`:hover`** в киосковом коде (в прототипах можно)
- ❌ **Внешние CDN** — киоск офлайн
- ❌ Самодельные тени, радиусы, отступы — есть шкалы `--sh-*`, `--r-*`, `--sp-*`

**Цвет только из брендбука** (`docs/brand/Lenin-guideline-2026.pdf`), палитра RAL.
Полутона — производные по формуле от бренд-цвета (`mix(paper-white, brass, 8%)`),
считает генератор. «Своих» цветов не бывает.

**`brand.html` — центральный каталог.** Новый визуальный примитив сначала
появляется там, только потом используется в разделе. Постановка задачи —
«свёрстай по `brand.html#c-spravka-card`», а не описание словами.

`npm run brand:lint` — обязателен перед коммитом.

**Он сейчас красный, и это не повод его игнорировать.** Долг зафиксирован
в `scripts/design/brand-lint.baseline.json` пофайловыми счётчиками: линтер
падает не на самом наличии нарушений, а на **приросте** к базе. Правило —
не трогать чужой счётчик и не гонять `--update-baseline`, чтобы «стало
зелено»: это стирает единственную метрику, по которой видно, кто добавил.

Две оговорки к текущим цифрам:
- База считалась до мержа `maps`, поэтому `demo-povolzhye.html`
  и `map-unit.js` показывают прирост, которого зона не делала.
- `R4` у карт — `var(--x)` на несуществующие `--wood`, `--paper-light`,
  `--paper-warm`, `--ochre`. Их не было и до мержа `design`: карта никогда
  не стояла на брендовой палитре, а рисовалась хексовыми fallback'ами.
  Разбор — в `docs/launch/m1d-maps.md`, задача 4.

Поэтому `brand:lint` **не входит в `npm run check`** — постоянно красный
гейт учит его пропускать. Войдёт, когда прирост будет обнулён.


## 9. Контент

`../IN/` — приёмник, кладём **как прислали**, не переименовываем, не чистим.
Материалы из корня `29-30/` собраны туда 2026-08-02: карты — `02-maps-src/`,
webm-стенд МТК 30 — `03-maps-webm/`, анимации — `04-media/`, референсы
и брендбук — `05-refs/`, ТЗ — `00-tz/`. В корне `29-30/` материалов
заказчика больше нет.
Новая версия файла кладётся рядом с датой в имени, старая не удаляется.

`docx → json` **только скриптом** (`scripts/import/`). Парсер — прямой разбор
`word/document.xml`: python-docx теряет текст гиперссылок, pandoc-таблицы
непарсимы надёжно.

**Трёхфайловая модель:** `<id>.gen.json` (машина) + `<id>.patch.json` (человек)
+ `<id>.json` (слияние). Машина никогда не пишет в файл, который правил человек.

⚠️ **Неверная ссылка хуже отсутствующей.** Автоматическая простановка
связей берёт только однозначные совпадения; похожее сразу на две
сущности уходит человеку. Неразрезолвленное упоминание остаётся жирным
курсивом и деградирует незаметно, а неверная ссылка уводит посетителя
не туда, и он этого не поймёт. Тот же принцип, что у перехваченной
тач-цели в §1.

**Идентификаторы** — `content-src/_ids.json`, append-only. Импортёр никогда
не переназначает существующий id. Иначе переимпорт осиротит уже наполненный
контент и привязанные карты.

**Медиа:** оригиналы в `../IN/`, производные — `npm run media:build` в
`public/content/media/` (в `.gitignore`). Тиры `lg` 2400×1500 / `sm` 1280×900 /
`xs` 560×560, WebP. У 44 % фонда длинная сторона < 1600 px — **лайтбокс
не должен апскейлить**, ставим `max-width` из натива.

**Английский** доливается позже через `.patch.json`. Схема `*_ru`/`*_en` готова.
Если в docx колонка EN содержит копию русского — пишем `null` + `en_status`,
иначе переключатель RU/EN покажет русский и это примут за баг движка.


## 10. Карты

**Модель: одна векторная география, территории — полигоны на ней.**
59 карт территорий — не 59 картинок, а полигоны в общей системе координат
+ таблица цветов по фазам.

⚠️ **Поправка 2026-08-03: «калибровать не нужно» верно только для ОБЗОРНЫХ
листов.** Зона `maps` проверила и опровергла. Обзорные (РСФСР ×4, СССР,
Временное правительство, Антанта, Колчак) — буквальные кропы ОБРАЗЦА, поворот
меньше 0.05°. Регионные (Северная область, ВСЮР, Дон, Оренбург, РВО,
Приамурье, ПЮР, Комуч, ЦД, ЧСК) на базу **не садятся**, и дело не в методе:
у базы Белое море сглажено и Соловков нет, у регионного листа береговая линия
подробная, с каждым островом. Это разные уровни генерализации, а подробность
масштабированием не добывается.

Решение: **база строится сразу по подробному источнику** — генерализацию можно
убрать, придумать нельзя. Тогда сядут и обзорные листы тоже.

**Канонический `viewBox` — пиксельное пространство ОБРАЗЦА, 1820×1180.**
Не меняется: подробный источник регистрируется в него. Полигоны, налитые
до смены базы, остаются валидными — пересчёта не будет.

Если бы это всплыло после полусотни полигонов, дефект был бы тихим:
территория в море, море на суше, и ни одной ошибки.

⚠️ **Якорей надо мало и близко.** «Взять побольше для надёжности» здесь
делает хуже: у схем Симбирска четыре местных якоря (Казань, Симбирск,
Самара, Сызрань) дают СКО 0.25 px, а с добавлением Перми и Вятки —
8.6 px. На большом охвате проекция уже кривая, и лишний якорь тянет
аффинное преобразование в среднее по кривизне.

⚠️ **Переиспользованный фрагмент SVG в чужом `viewBox` врёт по толщине.**
Всё, что задано в пользовательских единицах — толщина линий, кегль, —
масштабируется отношением кадров. У схем Симбирска кадр 31 против 302
у поволжской карты: первый прогон дал подписи в треть карты и стрелки
толщиной с реку. Класс общий, не картографический: работает там, откуда
взял, ломается там, куда положил.

Калибровка (`prototypes/empire-1914`) нужна только операционным картам —
фронтам и наступлениям, срисованным с атласных листов другого масштаба.
Привязка **на якорях** (город → координата), а не на матрицах: матрица
умирает при замене подложки, якоря переживают.

Два пайплайна: **HSV-маска + обводка контуров средствами OpenCV** (`cv2.findContours`; potrace в проекте не используется) для одиночной цветной заливки
(территории), **Quiver + `scripts/maps/*.py`** для операционных карт со
стрелками и подписями.

Рамка, заголовок, легенда, таймлайн фаз, выноски — **UI, а не запечённые
пиксели**.

webm из МТК 30 — только для того, что уже отрендерено. Одновременно
инстанцирован ровно один webm-набор, `<video>` уничтожаются при выходе.
