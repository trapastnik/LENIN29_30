# Схема контента МТК 29 — версия `schema: 1`

Владеет зона `content`. Ломающее изменение = бамп `schema` + правка этого
документа + предупреждение оркестратора.

Машиночитаемая часть — `public/content/_schema/*.schema.json`. Здесь то,
чего в JSON Schema не выразить: почему поля именно такие.

> ⚠️ **Ручные правки сгенерированных json запрещены.** Следующий прогон
> импорта их затрёт. Правка идёт либо в скрипт импорта, либо в
> `<id>.patch.json` — см. «Трёхфайловая модель».

---

## 1. Почему схема плоская

Суффиксы `_ru`/`_en` на самом поле, без вложенного объекта `i18n`.

Причина механическая, а не вкусовая: **только при плоских полях работает
stub-fallback**. `party-card.js:112-121` при 404 собирает карточку из записи
индекса. Это и есть режим постепенного наполнения — раздел живой, пока справки
доезжают. Вложенная структура сломала бы сборку карточки из индекса.

Так же уже устроены `party-card.js`, `state-card.js` и оба индекса.

## 2. Общий конверт

Все справки — `person`, `party`, `state`, `event` — делят один каркас.

| Поле | Тип | Смысл |
|---|---|---|
| `schema` | `1` | версия схемы |
| `id` | slug | из `content-src/_ids.json`, **append-only** |
| `kind` | enum | `person` · `party` · `state` · `event` |
| `camp` | enum¦null | `red` · `white` · `rev-dem` · `green` · `national` · `intervention` · `uprising` |
| `title_ru` / `title_en` | строка | заголовок |
| `sort_key_ru` | строка | ключ алфавитной сортировки: без кавычек, `ё→е`, lowercase |
| `dates` | объект | см. §3 |
| `summary_ru` / `summary_en` | markdown¦null | основной текст |
| `en_status` | enum | `ok` · `missing` · `copy_of_ru` — см. §6 |
| `media[]` | массив | см. §4 |
| `related{}` | объект | см. §5 |
| `notes[]`, `flags[]` | массивы строк | директивы верстальщику и метки аномалий |
| `src{}` | объект | происхождение: файл, номер, sha256, версия парсера |

### `src.no` и `src.ns` — метаданные, не идентификатор

Номера 01–71 в именах файлов заказчика **не годятся в id**: у «Территории» и
«Хроники» независимые пространства имён, и номера 7, 8, 20, 22–23, 26–28,
30–37, 40–47, 49–53, 55 заняты в обоих. Отсюда `ns`.

## 3. `dates`

```json
{ "from": "1917-10-24", "to": "1917-10-26", "precision": "day",
  "display_ru": "24–26 октября 1917 г.", "style": "single", "raw": "24–26 октября" }
```

- `from`/`to` — ISO `YYYY-MM-DD` либо `YYYY`. **Это подписи календаря, а не
  абсолютные моменты:** до февраля 1918 г. заказчик пишет по юлианскому стилю.
- `precision` — `day` · `decade` · `month` · `year` · `unknown`.
  `decade` — это «Конец/Начало/Середина месяца», границы 21–31 / 1–10 / 11–20.
- `display_ru` — строка заказчика как написана. **Приоритет при выводе:**
  «Конец октября – начало ноября» нельзя показать как «21.10 – 10.11».
- `style: "dual"` + `alt{}` — в источнике оба стиля: `15 (28) января`.
  Таких в хронике четыре.

**Парсер дат на безопасный отказ.** 296 различных форм записи разобраны
полностью, но правило остаётся: при неудаче — `precision: "unknown"`, а
сортировка падает на номер строки. Событие не имеет права потеряться из-за
нераспарсенной даты. Отчёт — `content-src/_dates-report.csv`.

## 4. `media[]`

```json
{ "n": 2, "slot": "gallery", "file": "media/states/rsfsr/02",
  "src_file": "01 РСФСР 02.jpg", "src_name": "01 РСФСР_02",
  "caption_ru": "Я. М. Свердлов – председатель ВЦИК. Фотограф П. А. Оцуп. Москва. Начало 1919 г.",
  "inv_ru": "ГМПИР. Ф.III-10291", "extra_ru": null,
  "w": 2125, "h": 1560, "tiers": [] }
```

**Аннотация, инвентарный номер и пояснительный хвост хранятся раздельно.**
Инв. номер выводится отдельной строкой мелким кеглем — музейное требование.
Слепив их, получаешь абзац текста под фото; в нынешнем `people-data.js`
именно так и сделано, и это **не образец**.

- `n` — порядковый номер в справке и **ключ слияния с патчем**.
- `w`/`h` — натив оригинала. У 44 % фонда длинная сторона < 1600 px, поэтому
  **лайтбокс не должен апскейлить** — `max-width` берётся отсюда.
- `tiers[]` — какие производные собраны. Пусто = `npm run media:build` ещё не
  гонялся. Валидатор проверяет, что каждый заявленный тир существует.
- `parts[]` — одна аннотация покрывает несколько файлов: две стороны купюры
  лежат как `01 РСФСР 05 1.jpg` и `01 РСФСР 05 2.jpg`.
- `note_ru`, `directives[]`, `duplicate_of` — из колонки ПРИМЕЧАНИЕ, §7.

## 5. `related{}` и ссылки в тексте

Граф связей **уже размечен заказчиком**: жирный курсив (`w:b` + `w:i` в одном
`rPr`) = упоминание другой сущности. 4804 фрагмента, 1568 уникальных фраз.

Ссылки кладутся **markdown-ссылкой прямо в текст**, не отдельным массивом со
смещениями: смещения ломаются при первой же ручной правке в патче.

```
"…приход к власти в столице [большевиков](#/party/bolsheviks)."
```

Неразрезолвленное упоминание остаётся `***жирным курсивом***` без ссылки —
деградация визуально незаметна, раздел не ломается.

`related{}` — те же связи, собранные по разделам (`persons`, `parties`,
`states`, `events`), для блока «Связанное». **Каждый id обязан существовать
в индексе** — это ошибка валидатора, не предупреждение.

Словарь `content-src/_aliases.json` — **ручной**: русский склоняется,
`большевиков` / `большевиками` / `большевики` — три формы одной сущности.
Сид генерируется (`run_import.py --seed-aliases`), дальше правится руками;
неразрезолвленное по частоте лежит в `content-src/_aliases-todo.csv`.

## 6. Английский — обезвреженная ловушка

**Ни одной переведённой справки из 198.** Колонка EN либо пуста (85), либо
в неё скопирован русский текст (113).

| `en_status` | что значит | что в `summary_en` |
|---|---|---|
| `missing` | колонка EN пуста | `null` |
| `copy_of_ru` | в колонке EN лежит русский | `null` — **обязательно** |
| `ok` | настоящий перевод | текст |

При `copy_of_ru` писать русский в `summary_en` нельзя: переключатель RU/EN
покажет русский, и на приёмке это примут за баг движка. Валидатор на этом
падает.

Английский доливается позже через `.patch.json`.

## 7. Колонка ПРИМЕЧАНИЕ — сохраняем, но не в контент

Там инструкции верстальщику: «Подрезать поля», «Разместить обе стороны купюры
на одной странице», «Использовалась в СВЕРДЛОВ» (последнее — указание на
дубликат изображения между справками).

→ `<раздел>/_notes.json`, ключ — id справки. Машиночитаемые директивы
дублируются в `media[].directives`: `trim` · `spread` · `duplicate_of`.

## 8. Расширения по видам

**person** — `short_ru`, `given_ru`, `surname_ru`, `regalia_ru[]`, `side`
(алиас `camp`: сцена `/expo/` читает `side`, карточки — `camp`).
Регистр строк сохраняется как в источнике (`ЛЕНИН (УЛЬЯНОВ)`) — приведение
регистра это вёрстка, а не данные.

**party** — `title_full_ru`, `abbr_ru[]`, `aka_ru[]`, `leaders_ru[]`,
`venn_groups[]`, `x`, `y`, `xy_locked`, `_is_general`.

> **`venn_groups` — массив, а не один `camp`.** Иначе смысл диаграммы Венна
> теряется: «Союз защиты Родины и свободы» визуально стоит между белыми и
> рев-демократией, а с одним `camp` сидит в одном круге. Заполняется вручную
> по 33 записям. Импорт ставит `[camp]` как заглушку и её не перетирает.

**state** — `abbr_ru[]`, `aka_ru[]`, `aka_raw_ru`, `participants_ru[]`,
`capital_ru`, `symbols[]`, `territory_id`.

> `territory_id` ссылается в `public/content/geo/_index.json` — реестр зоны
> `maps`. Нет полигона — `null`, UI показывает заглушку. Импорт этот id
> **не придумывает**, и заводить его «на будущее» нельзя.

**event** — `date`, `chronicle_refs[]`.

## 9. Хроника — файл на год

`chronicle/_index.json` + `1917.json`…`1922.json`. Максимум 139 записей
(1918) ≈ 60 КБ — одна загрузка на переключение года.

```json
{ "id": "ch-1917-001", "year": 1917, "row": 1, "sort": "1917-10-24#0001",
  "kind": "event", "date": { … }, "track": "pol",
  "pol_ru": "…", "mil_ru": null, "card": "oktyabrskiy-perevorot-v-petrograde",
  "refs": { "parties": ["bolsheviks"] }, "weight": 3 }
```

- **`track` трёхзначное, не булево**: 212 строк только политических, 153 только
  военных, **31 заполнена в обеих колонках**.
- **`row` авторитетен для порядка вывода**, `sort` — для фильтров и склейки
  лет. Это не одно и то же: неточные даты («Конец марта», «Март–апрель»)
  заказчик ставит **в конце** месячного блока, и сортировка по `from`
  переставила бы их вверх. Расхождений 20 из 396, все перечислены в
  `_dates-report.csv`.
- **`kind: "month-marker"`** — 19 строк, где в колонке даты стоит голый месяц
  («Ноябрь»). Из них sticky-заголовки и якоря скролла. ⚠️ Такая строка
  **всё равно несёт событие** — пустых среди них нет, это признак строки,
  а не отдельная запись-разделитель.
- `card` — мост к карточке события. Заказчик проставил его явной командой
  прямо в тексте: «Переход к справке 24 Открытие и разгон Учредительного
  собрания», ~77 вхождений. Команда — указание движку, а не контент: из
  текста она вырезается.

## 10. Индекс раздела — обязан быть самодостаточным

Зона `ui` переводит карточки на ленивую загрузку: плитка рендерится из
индекса, а при 404 карточка собирается из записи индекса. Поэтому в `items[]`
лежит всё нужное для плитки: `title_ru`, `abbr_ru`, `camp`,
`dates_display_ru`, `lead_media` + `lead_w`/`lead_h`, `has_card`,
`sort_key_ru`.

**В индексе есть запись на каждый закреплённый id**, даже если справка ещё
не импортирована — тогда `stub: true`. Индекс это единственная таблица
разрешения ссылок: нет записи — битая ссылка в `related`.

Импорт **не трогает кураторские поля**: координаты Венна (`x`, `y`),
справочник `camps[]`, фон диаграммы. Они пришли из зон `ui`/`design`.

## 11. Трёхфайловая модель

Заказчик пришлёт правки. **Машина никогда не пишет в файл, который правил
человек.**

```
public/content/persons/lenin.gen.json     ← перезаписывается импортом
public/content/persons/lenin.patch.json   ← правки руками, машина не трогает
public/content/persons/lenin.json         ← слияние, результат прогона
```

Слияние глубокое, патч выигрывает:

| Случай | Поведение |
|---|---|
| поле есть в обоих | побеждает патч |
| `null` в патче | **поле удаляется** (а не записывается `null`) |
| `media[]` | слияние по ключу `n`, остальные элементы сохраняются |
| прочие массивы | патч заменяет целиком |

Прогон печатает: новых / изменённых / без изменений / **конфликтов с патчем**.
Конфликт — импорт изменил поле, которое перекрыто патчем: значит заказчик
поправил ровно то место, что уже правили руками. Список — в
`content-src/_import-report.md`.

Идемпотентность подпирается `content-src/_manifest.json`: sha256 каждого docx
и версия парсера.

## 12. Как гонять

```bash
python3 scripts/import/seed_ids.py                     # разово: посев реестра id
python3 scripts/import/run_import.py --seed-aliases    # досев словаря алиасов
python3 scripts/import/run_import.py --pilot           # пилот вехи M1b
python3 scripts/import/run_import.py --kind state --only РСФСР
node scripts/validate-content.mjs                      # = npm run content:check
```

### Кросс-чек парсера

`content:check` параллельно гоняет **pandoc** и сравнивает объём извлечённого
текста с нашим. Прямой разбор `document.xml` умеет больше pandoc, и ровно
поэтому его некому проверить: независимый инструмент ловит класс ошибок
«обход дерева молча пропустил ветку». Расхождение > 2 % → предупреждение.

Пропускается молча, если нет `../IN/` или pandoc — на сервере сборки нет ни
того, ни другого, и деплой из-за этого падать не должен. Отключается
`--no-crosscheck`.

Небольшой законный дрейф бывает: pandoc отдаёт как текст `alt` встроенных
картинок. У `01 РСФСР.docx` это исходный путь файла флага — 3 %
расхождения, содержимое справки не затронуто. **Предупреждение — повод
посмотреть, а не повод менять допуск.**
