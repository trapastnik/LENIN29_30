## ⛔ Главное: `crossorigin` от vite убивает ВСЕ стили под `file://`

> **Закрыто оркестратором.** Плагин `mtk-strip-crossorigin` в `vite.config.js`
> плюс проверка в `check-paths.mjs`, чтобы не вернулось, — коммит `583fb32`.
> Замер воспроизведён независимо: атрибут стоял на всех восьми собранных
> страницах. Ниже — исходный разбор.

Это не про мою зону — это про весь проект, и видно только на приёмке.

Vite вешает `crossorigin` на каждый свой `<link rel="stylesheet">`. Под `file://`
атрибут включает проверку CORS для непрозрачного origin, стиль **молча не
применяется**. По http всё в порядке.

Проверено в настоящем Chrome, `file://`, две одинаковые страницы:

| Разметка | `background` из подключённого css |
|---|---|
| `<link rel="stylesheet" href="a.css">` | `rgb(1, 2, 3)` — применился |
| `<link rel="stylesheet" crossorigin href="a.css">` | `rgba(0, 0, 0, 0)` — **нет** |

На собранной странице это выглядело так: `font-family` заголовка — `Times`,
цвет — `rgb(0,0,0)`. То есть киоск показал бы разделы без бренда вообще.

**Заявка.** В `vite.config.js` (файл оркестратора) добавить плагин:

```js
// vite вешает crossorigin на свои <link>/<script>. Под file:// это включает
// проверку CORS для непрозрачного origin, и стиль молча не применяется —
// киоск остаётся без бренд-палитры и шрифтов. По http дефект не виден.
const stripCrossorigin = {
  name: 'mtk29-strip-crossorigin',
  enforce: 'post',
  transformIndexHtml: (html) => html.replace(/\s+crossorigin(?=[\s>])/g, ''),
};
```
и `plugins: [stripCrossorigin]`.

С ним проверено на собранной странице под `file://`: заголовок — `Nolde`,
цвет — `rgb(210, 183, 115)` (`--brass`), фон полосы — `--paper-white`.

## ⛔ Второе: `states.html` и `parties.html` под `file://` не работают

> **Закрыто оркестратором.** Лечится одним флагом запуска
> `--allow-file-access-from-files`; прописан в CLAUDE.md §1 и в обе команды
> в `docs/deploy.md`, коммит `0f2d972`. Замер оказался шире моего: пустыми на
> киоске были бы ещё и персоналии — `expo/people.html` отдавал 6 629 байт
> против 231 468 с флагом. Ниже — исходный разбор.

Тот же класс дефекта, зона `ui`. Замеры в настоящем Chrome под `file://`:

| Что | Результат |
|---|---|
| внешний классический `<script src>` | исполняется |
| внешний `<script type="module" src>` | **не исполняется** (CORS) |
| инлайновый `<script type="module">` | исполняется |
| `fetch()` / `XMLHttpRequest` | **падает** |

`states.html` и `parties.html` собраны как module-скрипты и грузят контент
через `fetch` — на киоске это пустая страница без ошибки в консоли. В
`docs/deploy.md` в проверке после деплоя стоят пункты «`/states.html` → 4 блока
групп» и «клик по Комуч → модалка с живой картой»: по http они пройдут, на
киоске — нет. Флага `--allow-file-access-from-files` в юните нет.

Мою страницу это не касается: `simbirsk.html` целиком на классических скриптах,
данные приходят через `window.MTK_LONGREADS` — тот же приём, что у сцены
`/expo/` (`data.js`, `people-data.js`).

## Заявки помельче

1. **Зарегистрировать страницу** в `vite.config.js` → `rollupOptions.input`
   (*принято, оркестратор делает при мерже*):
   ```js
   simbirsk: 'simbirsk.html',   // Раздел 5 · Лонгрид «Симбирск 1918–1919»
   ```
   Без неё страница не попадает в `dist/`, и это не заметно до приёмки.
   Собирал и проверял через временный конфиг в скретчпаде, сам файл не трогал.

2. **Скрипты в `package.json`** (файл оркестратора; *принято, `longread:check`
   идёт в `npm run check` при мерже*):
   ```json
   "simbirsk:import": "python3 scripts/simbirsk/import_simbirsk.py",
   "simbirsk:check":  "python3 scripts/simbirsk/import_simbirsk.py --check",
   "longread:build":  "node scripts/simbirsk/build-longread.mjs",
   "longread:check":  "node scripts/simbirsk/build-longread.mjs --check",
   ```
   и `longread:check` — в `npm run check`. Причина та же, что у `expo:check`:
   рантайм коммитится, и правка компонента без пересборки в киоск не доедет
   молча. `simbirsk:check` в `check` ставить не нужно — он требует `../IN/`,
   которого нет на сервере сборки.

3. **`content-src/_ids.json`** (зона `content`): завести `kinds.longread.simbirsk`.
   Реестр append-only и не мой, поэтому не трогал. Сейчас `kinds.longread` пуст.

4. **`public/content/longreads/_index.json`** — по §4 все `_index.json` кроме карт
   у зоны `content`, поэтому не заводил. Пока он никому не нужен: страница грузит
   `simbirsk.data.js` напрямую. Понадобится, когда лонгридов станет больше одного.

5. **`scripts/validate-content.mjs`** (зона `content`) каталог `longreads/` не
   проверяет вообще. При этом `PLURAL` в нём уже знает про `longreads`, а
   `common.schema.json` — про `kind: "longread"`, то есть место оставлено.
   Просьба к `content` подключить каталог: сейчас битую ссылку в лонгриде
   `content:check` не поймает.

6. ~~**Спорное место, прошу ратифицировать.**~~ **Решено: переехало.** Собранный
   рантайм лежал в `public/content/longreads/longread-runtime.js` — код внутри
   каталога зоны `content`, где его рано или поздно затёр бы прогон импорта.
   Перенесён в **`public/longread/longread-runtime.js`**; оркестратор закрепляет
   каталог за зоной `simbirsk` в §4 при мерже. Данные лонгрида остались
   в `public/content/longreads/` — там им и место.

   Почему рантайм вообще обязан лежать в `public/**`: классический
   `<script src>` иначе не доедет. Vite такой файл не эмитит — печатает
   «can't be bundled without type="module"», оставляет путь как есть, и в
   `dist/` его просто нет. Verbatim копируется только `public/**`.

## Для зоны `design`

В `tokens.json` нет двух токенов, которые описаны в `docs/launch/m1a-design.md`:

- **`--camp-uprising`** — а лагерь `uprising` в `common.schema.json` есть, и на
  нём сидит `chapannaya-voyna`, которую лонгрид показывает в связях. Обошёл
  белым списком лагерей в `longread-section.js`: неизвестный лагерь уходит на
  `--accent-alt`. Появится токен — уберу.
- **`--ui-scale`** — задание M1e требует «×2 на киоске через `--ui-scale`».
  Токена нет, поэтому вёрстка в фиксированных логических пикселях, как на
  остальных страницах.

`brand:lint` по моим файлам чистый: прирост ноль. Остальные регрессии в отчёте —
`maps` (`demo-povolzhye.html`, `map-unit.js`) и `ui` (`public/expo/build/*`),
то есть ровно то, что описано в CLAUDE.md §8.

Мелочь на будущее: линтер маскирует только `/* */` и `<!-- -->`, но не `//`.
Из-за этого он ругался на hex и `var(--…)`, упомянутые в обычных комментариях.
Переформулировал у себя, но правило стоит поправить — оно наказывает за
объяснение правила в комментарии.

## Что проверено

Ворота:

- `npm run check` — падает на `paths:check` в трёх известных местах
  (`map-unit.js`, `brand.html`, `calendar.html`, CLAUDE.md §2). По моим файлам
  чисто, проверял тем же регэкспом по собранной странице и артефактам.
- `npm run content:check` — «Ошибок нет».
- `npm run brand:lint` — прироста по зоне нет.
- `simbirsk:check` и `longread:check` — артефакты совпадают с источниками.

Собранная страница под `file://` в настоящем Chrome (не в превью — превью
разрешает `file://`-fetch и потому врёт):

- 11 разделов, 24 абзаца, 42 плашки связей, оглавление на 11 строк;
- **иллюстраций отрисовано 0** — ни рамок, ни «фото будет позже». Разделы 2, 5,
  10 в источнике вообще без картинок и выглядят законченными;
- заголовки — `Nolde`, `font-style: normal` (синтетического курсива нет, §8);
  лид — курсив `21 Cent`, у которого начертание существует;
- тач-цели: строка оглавления 120 px, плашка связи 158 px, кнопки пагинатора
  120×120;
- `:hover` в разметке нет;
- переход по оглавлению и пагинатору ставит раздел под шапку (top = 140 px),
  счётчик совпадает с разделом.

Две вещи всплыли только на этой проверке, обе чинились:

- **плавная прокрутка живёт на кадрах анимации, а кадров может не быть.**
  `scrollIntoView({behavior:'smooth'})` не сдвигал страницу ни на пиксель, при
  этом счётчик разделов честно перещёлкивал — интерфейс врал. Причём
  `document.visibilityState` при этом «visible», так что проверка на скрытую
  вкладку одна не спасает. Сделан свой твин плюс таймер, который доводит
  позицию, если кадры так и не пошли.
- **наблюдатель пересечений сбрасывал счётчик.** Его первый отчёт приходит
  асинхронно и описывает положение на момент замера: после нажатия в оглавлении
  он сообщал «виден раздел 1» и откатывал счётчик на «01», хотя страница уже
  стояла на восьмом. На время перехода наблюдатель заглушается.

Утечки: наблюдатель, кадр анимации, таймер и слушатель клавиатуры снимаются
в `disconnectedCallback`; после перехода не остаётся ни одного висящего
дескриптора (проверено).

## Чего в этой вехе нет

- **Иллюстраций.** Их не поставили: в docx 0 изображений. Компонент
  `longread-media` написан и умеет тиры и натив без апскейла, но рисует только
  слот с реальным `file`. Наполнение — через `simbirsk.patch.json`, слияние по
  ключу `n` уже работает.
- **Английского.** В источнике колонки EN нет вообще, поэтому `en_status:
  "missing"`, все `*_en` — `null`. Схема двуязычная, долить можно патчем.
- **Перехода в карточку по нажатию.** Плашка ведёт на `states.html#/state/komuch`
  и подобные — форма хэша из `docs/content-schema.md`. Роутера по хэшу ни на
  одной странице пока нет, поэтому нажатие открывает раздел, но не карточку.
  Это зона `ui`; когда роутер появится, ссылки заработают без правок здесь.
- **Двух карт-схем**, которые в источнике помечены «см. литература»: бои за
  Симбирск (июль 1918) и Симбирская операция (сентябрь 1918). Это работа зоны
  `maps`, её никто не ставил.
- **Claude Design** не применялся. §11 его здесь разрешает, но экспорта нет;
  вёрстка собрана из существующих примитивов `pages.css` и токенов.
