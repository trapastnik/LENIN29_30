## Парсер: прямой разбор `word/document.xml`

**Не python-docx** — он не возвращает текст `w:hyperlink`, а в справках есть
ссылки. **Не pandoc как парсер** — его grid-table markdown непарсим надёжно
(ширины ячеек, переносы внутри ячейки, объединённые ячейки схлопываются).

`xml.etree.ElementTree` из stdlib даёт всё сразу:

| Что нужно | Откуда |
|---|---|
| текст гиперссылки | обход `w:hyperlink//w:t` наравне с `w:r//w:t` |
| URL | `word/_rels/document.xml.rels` по `r:id` |
| перекрёстные ссылки | `w:rPr` содержит одновременно `w:b` и `w:i` |
| имя файла картинки | `w:highlight` + первая строка ячейки |
| объединённые ячейки | `w:tcPr/w:gridSpan/@w:val` |

pandoc остаётся как **кросс-чекер QA**: `content:check` прогоняет его
параллельно и сравнивает длину извлечённого текста; расхождение > 2 % →
предупреждение «парсер что-то потерял».

## Структура скриптов

```
scripts/import/
  docxlib.py        общий низкий уровень: read_table, plain, rich, label_of
  ids.py            реестр идентификаторов
  rudate.py         русские даты → сортируемые ключи
  richtext.py       runs → markdown со ссылками
  media_link.py     имя из docx → файл на диске
  entity_{person,party,state,event,chronicle,longread}.py
  run_import.py     CLI-оркестратор
```

`label_of()` — словарь синонимов, разброс реальный:
`Аббревиатуры` / `Аббревиатура` / `Сокращения` → `abbr`;
`Период существования` / `Период` / `Годы деятельности` → `dates`.
Нормализация: lowercase, `ё→е`, срезать пунктуацию, длина < 40.

**Личности — эвристики, не индексы** (подписей полей нет, форма плавает):
годы жизни по `\d{4}(\(\?\))?\s*[–—-]\s*\d{4}` (строка 4 у большинства),
фамилия — последняя строка прописными перед годами, медиа-строка по трём
сигналам (подсветка / имя файла по маске / `ГМПИР` во втором абзаце), любые
два из трёх дают срабатывание.

**«Белые» устроены иначе остальных групп** — спецкода не пиши. Правило одно:
**единица справки = docx-файл, а не папка**, медиа-скоуп = папка этого файла.
Покрывает и плоские группы, и подпапки.

## Идемпотентность — трёхфайловая модель

Заказчик пришлёт правки. Машина никогда не пишет в файл, который правил человек.

```
public/content/persons/lenin.gen.json     ← перезаписывается импортом
public/content/persons/lenin.patch.json   ← правки руками, машина не трогает
public/content/persons/lenin.json         ← слияние, npm run content:build
```

Глубокий merge, patch выигрывает, массивы `media` мержатся по ключу `n`,
`null` в патче = «удалить поле». Плюс `content-src/_manifest.json` с sha256
каждого docx и версией парсера. Прогон печатает: новых / изменённых /
без изменений / **конфликтов с патчем**.
