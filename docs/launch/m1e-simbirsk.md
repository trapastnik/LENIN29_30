## ⚠️ Главное, что надо понять до начала: картинок нет

В docx **ни одного встроенного изображения**. Иллюстрации заданы двумя
способами, и оба — не файлы:

- 13 ссылок вида `https://goskatalog.ru/portal/#/collections?id=67744736`;
- 9 строк «Нужно подобрать: портрет М. А. Гимова; виды Симбирска 1917–1918…».

То есть **часть иллюстраций заказчиком ещё не поставлена**, а часть лежит во
внешнем каталоге, куда киоск ходить не может — он офлайн (§1).

Отсюда порядок работы: **вёрстка не должна ждать картинок.** Сделай так, чтобы
раздел без иллюстрации выглядел законченным, а не сломанным. Слоты под
изображения описываешь в схеме сразу, наполняешь по мере поставки.

Первым делом выпиши все 13 ссылок и 9 запросов в `content-src/simbirsk-media-wanted.md`
и отдай оркестратору — это вопрос заказчику, а не твоя задача его решать.
Ссылки из docx **не выкачивай**: это внешний источник, права на изображения
отдельный разговор.

## Задача 1 — схема лонгрида

`public/content/longreads/simbirsk.json` + `public/content/_schema/longread.schema.json`.

Опирайся на существующие: у всех есть `schema: 1`, поля `*_ru`/`*_en`,
и `en` пока `null` — **английского нет ни в одной справке** (§9), схема
двуязычная, наполнение придёт позже через `.patch.json`.

Структура напрашивается из исходника: лонгрид → массив из 11 секций, у секции
заголовок, подзаголовок, абзацы, слоты медиа и связи. Точную форму согласуй
с `content` до того, как разберёшь все 11 разделов.

**docx → json только скриптом** (§9). Ручная перепечатка запрещена по той же
причине, что и везде: следующая версия файла от заказчика затрёт правки.
Парсер бери у `content` — `scripts/import/` уже умеет `word/document.xml`
и решает проблему разрыва текста на соседние `runs`.

## Задача 2 — связи с уже импортированным

Лонгрид не пересказывает справки, а ссылается на них. В контенте **уже есть**:

| Сущность в тексте | Карточка |
|---|---|
| Комуч (разделы 5–8) | `public/content/states/komuch.json` |
| Чапанная война (раздел 10) | `public/content/states/chapannaya-voyna.json` |
| Каппель (раздел 4) | `public/content/persons/kappel.json` |
| Тухачевский (раздел 8) | `public/content/persons/tukhachevsky.json` |

Плюс события `nastuplenie-vostochnogo-fronta-rkka` и
`vesennee-nastuplenie-russkoy-armii` упоминают Симбирск.

Дублировать их содержимое в лонгриде не надо — заведи в схеме ссылки по `id`,
UI откроет карточку. Идентификаторы — из `content-src/_ids.json`, они
append-only, свои не выдумывай.

## Задача 3 — страница

`simbirsk.html` + `src/components/longread-*.js`.

**Обязательное с первой строки, а не потом:**

- **Пути только через `MTK_URL()`**, ни одного ведущего слэша (§5). `base.js`
  подключается первым скриптом: `<script src="base.js"></script>`. Киоск
  работает с `file://`, где `/content/…` уходит в корень файловой системы —
  раздел выходит пустым **без ошибки в консоли**. Ловится `npm run check`.
  Зона `ui` только что закрыла по этому контракту 21 место; не заводи новых.
- **Никакого `:hover`** — тач-панель (§8). Только `:active`, тач-цель ≥ 120px.
- **Цвет только из токенов** — `var(--…)` без hex-fallbacks. `var(--x, #hex)`
  запрещён отдельным правилом: это скрытая вторая палитра, которая молча
  включается при опечатке в имени. Нужен новый цвет — заявка в `design`.
- **Один непрерывный сеанс.** Лонгрид на 11 разделов с изображениями — первый
  кандидат на утечку. Если делаешь ленивую подгрузку, убирай и слушатели.

Верстаешь в 1920×1080 логических, на киоске ×2 через `--ui-scale`.

## Claude Design здесь разрешён

§11 прямо называет Симбирск среди мест, где его применять можно (в отличие от
хаба, хроники и карт). Правила те же: экспорт кладётся в
`src/design-lab/<YYYY-MM-DD-тема>/`, **не в рабочие страницы**, приёмку делает
`design`. Из экспорта нельзя тащить CDN, свои глобальные стили, роутинг
и структуру контентных JSON.

⚠️ §11 упоминает `npm run design:brief` для генерации брифа с дампом токенов.
**Такого скрипта нет** — он описан, но не написан. Актуальную палитру бери
из `src/design/tokens.json` и `brand.html`, по памяти не пересказывай.
