## Гейты зоны `ui` (механические проверки собранного `dist`)

Все — Chrome `--headless=new` через Bash в каноне §5 (окно 1920×1080 +
`--force-device-scale-factor=2` → CSS 1920 при DPR 2). НЕ панель браузера:
там `visibilityState: hidden`, ResizeObserver/rAF не доставляются. Каждый
поднимает свою статику на своём порту, профиль Chrome уникален на процесс
(`+pid`) и убирается в `exit` — иначе мигание и мусор в TMPDIR.

| Гейт | Файл | Что мерит | baseline |
|---|---|---|---|
| `paths:check` | `scripts/check-paths.mjs` | абсолютные пути, crossorigin, битые ссылки в dist | — |
| `css:order` | `scripts/check-css-order.mjs` | где порядок `<link>`/inline-`<style>` в dist решает исход | `check-css-order.baseline.json` |
| `touch:check` | `scripts/check-touch-targets.mjs` | ПОПАДАНИЕ (elementFromPoint), не computed-стили; 9 сцен, 307 целей; недобор по нижней границе из индексов | `check-touch-targets.baseline.json` |
| `contrast:check` | `scripts/check-contrast.mjs` | контраст по ФАКТИЧЕСКОМУ пикселю (captureScreenshot), не разбором CSS; `--self-test` | `check-contrast.baseline.json` |
| (deep-links) | `scripts/check-deep-links.mjs` | карточка по `#card=<id>` ОТРИСОВАНА (модалка+апгрейд+rt-ref), битый id даёт плашку, хэш стёрт | — |

`touch:check`, `contrast:check`, `css:order`, `paths:check` — в `npm run check`
(регистрирует оркестратор в `package.json`). `check-deep-links` пока отдельной
командой. `--update-baseline` фиксирует известное; падаем на приросте (§13).

**Ключевые ловушки замера, зашитые в код (не повторять руками):**
- `elementFromPoint`/`el.contains` НЕ проходят сквозь shadow DOM — спуск и подъём по хостам вручную;
- дискретные положения прокрутки — выборка; спорные цели доводятся `scrollIntoView`;
- оверлей (оглавление, модалка) накрывает цели → сбор сужается до оверлея;
- `<map-unit>` до первой доставки ResizeObserver врёт о размере → ждать ненулевой `transform` у `#container`;
- контраст: фон брать пикселем, буквы/фон делить по топ-3 частым цветам (дальний от текста = фон);
- ширина текста — только после `document.fonts.ready`.

### Долг гейтов
- `check-touch-targets` `--self-test` (готовность карты) **написан и НЕ проходит** — MutationObserver не ловит момент появления `map-unit`; оставлен красным честно, в ворота не входит. Довести.
- сцены «карточка с картой» в touch нет — модалка-оверлей, сужение до `#modal` не сработало.

## Модули (переиспользуемые)

- **`src/data/deep-link.js`** — глубокие ссылки `#card=<id>`. Форма: хэш стирается сразу после чтения (`replaceState`) — иначе сброс сеанса откроет чужую справку следующему; внутри страницы хэш не трогается (openModal напрямую); нет карточки → видимая плашка. Подключён на `parties.html` и `states.html`.
- **`src/data/related-rail.js`** — рельс связанных: `_backlinks.json` → три секции (out/refs/mutual) → чипы. `railHTML(entry,lang,curPage)` строка, `wireRail(root,onOwn)` навигация. `kind` (person/party/state/event) → страница.
- **`src/data/rich-text.js`**, **`src/data/i18n.js`**, **`src/data/loader.js`** — рендер markdown справок, язык (`expo:lang`), LRU-кэш fetch.

## Каркас рельса связанных (`de4145e`) — НА РЕВЬЮ ПЕРВЫМ ДЕЛОМ

**Готов эталон на `parties.html`** (в `party-card.js`): двухколоночная карточка
при `expanded` (`:has(.related-rail)`), чтение слева + рельс 380px справа со
своим скроллом, три секции, чипы ≥64px. Навигация: own-чип (kind=party) →
событие `rail-open` → `parties.html` openModal; чужой → переход `<page>#card=<id>`.

**Это КАРКАС (структура ui), не финальный вид.** Точки чипов — серые заглушки
(`.rail-chip__dot`). Цвет лагеря, кольцо, метку даст примитив `brand.html#c-related`
от `design` — вставится в готовую разметку, рельс не переверстывается.

**Что осталось (после ревью эталона):**
1. те же три секции в **`state-card`** (+ развязка с картой: карта сверху рельса, связи под ней);
2. в **people-detail** (`people-ui.jsx`, React — но `related-rail.js` переиспользуется, `railHTML` это строка).

⚠️ Не тиражировать до ревью структуры эталона — чтобы не встроить трижды то, что придётся переверстать.

**Остаток базы (16) — весь за `design`,** один корень «яркий цвет как мелкий текст»:
- Венн 7 (её палитра чипов);
- золото на светлом (главная 3 + хроника 2) → нужен `--brass-ink` (не существует);

Три текстовые потребности палитры оркестратор досылает design единым правилом «ink-вариант под фон».
